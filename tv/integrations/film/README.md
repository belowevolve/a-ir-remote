# Дополнительные модификации film.mov

film.mov — проект [gamahacka](https://github.com/gamahacka/filmmov). [Официальный канал](https://t.me/filmmov_app) · [Поддержать автора](https://t.me/tribute/app?startapp=dSVL).

Это технический гайд по дополнительным модификациям для личной установки и интеграции с Air Home. Исходный film.mov скачивается у автора; готовые модифицированные APK в этом репозитории не распространяются.


Адаптер добавляет в ТВ-версию film.mov выдачу постеров без встроенных бейджей. Air Home рисует сезон и эпизод поверх чистого изображения.

Маршрут: `content://mov.film.tvart/clean?poster=<URL>`. Используется локальный кэш film.mov; при отсутствии оригинала лаунчер пробует сетевой постер, затем исходную картинку провайдера.

## Сборка патча

Полная сборка из официального APK, включая тему, метаданные, бейджи,
MediaSession, исправления плеера и автономный обновлятор:

```sh
python3 tv/integrations/film/build.py /path/to/filmmov.apk \
  --output artifacts/film-tv-personal.apk \
  --keystore /private/film-local.p12 --alias film-local \
  --ks-pass-file /private/film-password
```

Для телефонной сборки добавьте `--phone`. Нужны JDK 25 и Android SDK
с платформой 35 и build-tools 36. Apktool скачивается с закреплённым SHA-256.
Проверены официальный релиз 4.0 (245) и перенос его рецепта на Android.
Сборщик ничего не устанавливает и не удаляет. Храните отдельный ключ film.mov:
он встраивается только в личный APK для автономного обновления. Ключи Air Home
и Air Remote сборщик отвергает до экспорта приватного ключа.

Ниже — отдельные этапы для изменения конкретной модификации.

Нужен ТВ APK с метаданными Air Home, Android SDK, JDK и apktool:

```sh
python3 tv/integrations/film/patch_clean_artwork.py /path/to/film-tv.apk \
  --apktool /path/to/apktool.jar --output artifacts/film-tv-patched.apk
```

Скрипт проверяет структуру APK, запускает проверки кэша и подписывает результат. Подпись должна совпасть с исходной. Ключ задаётся через `--keystore`, `--alias`, `--ks-pass-file`; по умолчанию используется стандартный Android debug-ключ.

Устанавливайте результат поверх ТВ-версии, без удаления приложения и его данных. Патч не предназначен для телефона.

Java-файлы здесь — автономные адаптеры для javac/D8; Kotlin runtime в сторонний APK не добавляется. Исходный APK, ключи и результаты сборки в репозитории не хранятся.

## Компактные бейджи

`patch_badges.py` добавляет формат «Плашка сезона»: номер сезона на светлом левом сегменте во всю высоту бейджа, затем подпись «5 серия» с отступами. Шрифт и размеры совпадают с Air Home и заданы в `shared/PosterBadgeSpec`. Сохраняются подпись, ресурсы и данные приложения.

```sh
python3 tv/integrations/film/patch_badges.py /path/to/film.apk \
  --output artifacts/film-season-tag.apk
```

Если адаптера в APK ещё нет, добавьте `--apktool /path/to/apktool.jar`. При повторном применении заменяется только DEX адаптера.

Патч работает с телефонной и ТВ-версиями. Для каждого устройства используйте его исходный APK и прежний ключ подписи; устанавливайте поверх приложения без удаления данных.

## Обновление с патчем на устройстве

В личную сборку можно встроить строку **«Обновить с патчем»** в разделе
**Настройки → Приложение**. Она загружает стабильный релиз из официального
GitHub, проверяет SHA-256 и сертификат автора, применяет локальный рецепт,
подписывает APK прежним ключом и передаёт его системному установщику Android.
Обычная кнопка установки film.mov также проходит через этот патчер.
Данные приложения не удаляются. Компьютер, сервер и ADB для этой операции
не нужны; разрешение на установку из film.mov и подтверждение Android нужны.

Сначала подготовьте исходный APK и соответствующий ему APK со всеми нужными
патчами (палитра, метаданные, чистые постеры для ТВ, плашки). Затем:

```sh
python3 tv/integrations/film/add_updater.py original.apk patched.apk \
  --output artifacts/film-with-updater.apk \
  --keystore /private/film-local.p12 --alias film-local \
  --ks-pass-file /private/film-password
```

Сборщик использует JDK, Android SDK 35/36 и явно указанный отдельный ключ
film.mov. Kotlin в стороннее приложение не добавляется.
Исходники автономного патчера находятся в `updater/`; Gradle-проект собирается
отдельно от Air Remote. Зависимости изолируются от библиотек самого film.mov.

Рецепт изменяет только проверенные участки кода и ресурсов и переносится в
каждое следующее обновление. Новый код и остальные файлы берутся из нового
официального APK. При изменении затронутых участков, ID ресурсов, манифеста
или подписи установка останавливается с объяснением: потребуется обновить
рецепт на компьютере. Это не универсальная поддержка любых будущих версий.

**APK с автономным обновлением предназначен только для личных устройств:**
он содержит локальный ключ подписи, необходимый для обновления поверх
установленной сборки. Этот ключ извлекается из APK и не защищает от чужой
переподписи film.mov; не используйте его для других приложений. Публичные
Air Home и Air Remote имеют независимые ключи, которых в film.mov нет.
Чтение палитры Air Home не требует общей подписи: это отдельный доступ только
на чтение цветов и назначений кнопок, без изменения настроек или запуска действий.
APK, рецепт и экспорт ключа не публикуйте и не добавляйте
в Git. Сборщик хранит экспорт ключа только во временной папке и внутри APK.

Проверка на отдельном эмуляторе: `updater/src/deviceTest/`. Она выполняет
настоящую сборку на Android, сверяет версию и исходные native/raw-файлы,
проверяет повторное встраивание обновлятора и отказ при чужой подписи,
затем предлагает переустановить собранный APK. На личных устройствах этот
тест не запускайте: он создаёт тестовую запись в настройках.

## Воспроизведение после сворачивания

В ТВ-версии 4.0 (240) `PlayerActivity.onStop()` ставит плеер на паузу только
после подготовки и фактического начала воспроизведения. Если уйти на главную
во время загрузки, `playWhenReady` остаётся включённым, а поздний callback
может начать воспроизведение в фоне.

`patch_player_lifecycle.py` снимает это ограничение: при сворачивании
плеер останавливает автозапуск также во время буферизации. Три отложенных
вызова `play()` проходят через проверку состояния Activity. Picture-in-Picture
сохраняет штатное поведение. При возврате на экран воспроизведение разрешено.

```sh
python3 tv/integrations/film/patch_player_lifecycle.py film-with-updater.apk \
  --output artifacts/film-tv-lifecycle.apk \
  --keystore /private/film-local.p12 --alias film-local \
  --ks-pass-file /private/film-password
```

Нужны собранные зависимости `updater/build/runtime`, JDK и Android SDK build-tools
36.0.0. Заменяется только класс PlayerActivity; манифест, ресурсы и остальные
классы сохраняются. Если APK содержит автономный обновлятор, изменение
включается в его рецепт. При изменении ожидаемых lifecycle-методов или вызовов
в новой версии скрипт отказывается собирать APK. Устанавливайте поверх приложения
с прежним ключом без удаления данных.

На Haier проверка `tests/PlayerLifecycleRegression.java` использует настоящий
неподготовленный ExoPlayer, сворачивает PlayerActivity через HOME и проверяет,
что `playWhenReady` сброшен, поздний callback не включает звук, а запуск
при открытой Activity разрешён. Тест воздействует на реальное приложение.
Аргумент `-e fixtureUrl http://HOST:PORT/delayed.mp4` должен указывать на короткий
беззвучный MP4 с задержкой ответа: тест ждёт настоящей готовности плеера
уже после сворачивания. Для защиты истории на время проверки задайте
`debug.filmmov.nohistory=1`, после верните прежнее значение.

## Системное управление воспроизведением

`patch_media_session.py` публикует настоящий Media3-плеер через Android
`MediaSession`: позицию, длительность, скорость и доступные действия. Поддерживает
play/pause, seekTo и штатные кнопки следующего/предыдущего видео.
Air Home использует тот же `MediaController.TransportControls.seekTo`, что для
других совместимых плееров. Отдельного протокола перемотки film.mov нет.

```sh
python3 tv/integrations/film/patch_media_session.py film-tv-lifecycle.apk \
  --output artifacts/film-tv-media-session.apk \
  --keystore /private/film-local.p12 --alias film-local \
  --ks-pass-file /private/film-password
```

Основа — APK с исправленным lifecycle. Нужны зависимости `updater/build/runtime`,
JDK и Android SDK. Заменяются только PlayerActivity и автономный Java-адаптер;
манифест, ресурсы и остальные классы сохраняются. При наличии обновлятора хуки
и адаптер включаются в его рецепт. Сборщик проверяет ожидаемые методы и поле
плеера; несовпадение структуры останавливает сборку.

Сеанс существует только между onStart и onStop, слушатель обновляет его по
событиям Media3 без опроса таймером. При замене экземпляра плеера слушатель
переподключается. Перемотка сохраняет playWhenReady и ограничивает позицию
границами видео; прямой эфир без seek не объявляет поддержку seekTo.
Фоновый сервис, уведомление и новые разрешения film.mov не нужны.

Для управления другими приложениями Air Home нужен системный доступ к медиа
через включённый NotificationListenerService — см. [настройку Air Home](../../README.md#системная-перемотка).
Содержимое уведомлений не обрабатывается.

`tests/VoiceSeekRegression.java` использует реальный ExoPlayer и беззвучный
30-минутный MP4; проверяет команды с телефона +15 / -5 минут, сохранение паузы,
границы и освобождение MediaSession после сворачивания. Аргумент `fixtureUrl`
указывает на локальную тестовую запись. Для проверки нужен свободный ТВ.

## Цвет индикаторов загрузки

DynamicTheme задаёт цвет всем создаваемым `ProgressBar`, включая загрузку
каталога и карточек, открытие фильма, поиск источников, диалоги и плеер.
В версии 4.0 (245) покрыты все 23 места создания. Круговые и заполненные
индикаторы используют `accent_hot`, вторичный прогресс и дорожка — `accent_soft`.
Палитра берётся из памяти; анимация не обращается к провайдеру Air Home.

Изменение входит в обычную сборку `build.py` и рецепт автономного обновления.
Отдельный патч только двух индикаторов PlayerActivity больше не применяется.
