# Проверка исправлений пульта

## Несколько телефонов

На Haier Android TV PRO (Android 14) изучена установленная служба
`com.google.android.tv.remote.service`. Её `KeyStoreManager.storeCertificate`
удаляет предыдущие сертификаты с совпадающим `getSubjectX500Principal().getName()`
перед сохранением нового сертификата. У старого Air Remote это всегда
`CN=Air Remote`: повторное сопряжение другого телефона вытесняет первый.

Исправление: отдельный UUID в subject сертификата каждой установки, постоянный
ключ `air-remote-client-tls-v2` в Android Keystore. Старый ключ сохраняется для
ранее сопряжённых телевизоров. При успешном новом сопряжении только этот ТВ
переключается на новый ключ. Для исправления старых конфликтующих сопряжений
нужно обновить и заново сопрячь каждый телефон.

Проверить на двух телефонах: сопрячь A, затем B, отправить команды с обоих;
закрыть и открыть A, затем B; убедиться, что новый PIN больше не требуется.
Одновременное использование двух физических телефонов пока не проверено.

## Голос ТВ

Служба ТВ посылает `RemoteVoiceBegin`, когда приложение открывает распознавание
речи. Старый клиент принимал его только после собственного KEYCODE_SEARCH и
игнорировал запрос из приложения ТВ. Теперь запрос сохраняется, кнопка
«Говорить» подтверждает именно эту сессию; KEYCODE_SEARCH не отправляется.
`RemoteVoiceEnd` прекращает запись; новая сессия делает старые пакеты неактуальными.
Пакет уменьшен с 20 до 8 КиБ (512 мс при 8 кГц PCM16); искусственная тишина
к каждому короткому чтению не добавляется. Совместимость запросов конкретного
приложения и распознавание речи требуют проверки на ТВ.

## Клавиатура и ПК

На RMX5061 выполнен `InputRegressionRunner`: реальный InputConnection с вложенными
batch edits, выбором подсказки, заменой выделенного слова и composing spans.
Проверен также постоянный уникальный сертификат Android Keystore. Все проверки прошли.

Повторный запуск:

```sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
adb -s PHONE install -r app/build/outputs/apk/debug/app-debug.apk
adb -s PHONE install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s PHONE shell am instrument -w belowevolve.airremote.dev.test/belowevolve.airremote.InputRegressionRunner
```

На Windows осталось проверить: возвращение после случайного разрыва Bluetooth,
отсутствие автоподключения после ручного отключения, Shift RU/EN, индикатор Caps
Lock, перенос пальца при выделении области скриншота и немедленное отпускание
кнопки при выходе с экрана трекпада. Android может снимать регистрацию HID в фоне;
повторы в активном приложении не гарантируют сохранение фонового соединения.

Дополнительно подтверждено по установленной службе Haier: в направлении телефон →
ТВ поле 31 — сырые PCM bytes, а в направлении ТВ → телефон поле 31 — сообщение
окончания с session_id. Прежняя общая схема ошибочно трактовала оба направления
как вложенный RemoteVoicePayload. Введено отдельное клиентское сообщение; wire-тест
проверяет точные байты. В логах до исправления видны также запоздалые подтверждения
закрытых сессий. Реальное распознавание слов после исправления ещё нужно проверить.

## Уточнение 0.1.5

Запись автоматически начинается по RemoteVoiceBegin, пока приложение открыто
в режиме ТВ. При отсутствии разрешения вызывается системный запрос Android;
при активном микрофоне ПК вторая запись не запускается. При замене голосовой
сессии сначала завершается предыдущий AudioRecord. Уведомления «ТВ ждёт голос»
и промежуточного нажатия «Говорить» больше нет.

На RMX5061 и Haier проверено: открытие голосового ввода на самом ТВ автоматически
включило запись в приложении (индикатор «Стоп»), служба ТВ приняла voice config
8000/16/2. После закрытия ввода на ТВ запись прекратилась. Распознавание конкретных
слов этой проверкой не оценивалось.

Экран клавиатуры проверен на телефоне: без верхней панели и крестика, поле
«Введите текст», нижний ряд с «Отмена» слева и удалением/вводом справа.
