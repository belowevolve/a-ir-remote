# Проверки на устройстве

UI-раннеры на платформенном SDK, например `ModalRegressionRunner`, могут работать с минифицированным release APK. Проверки внутренних классов и голосовые runners используют соответствующий debug APK. Тестовый APK должен быть подписан тем же ключом, что и приложение.

```sh
./gradlew :app:assembleStandardDebugAndroidTest
# Для голосовых проверок:
./gradlew :app:assembleVoiceDebug :app:assembleVoiceDebugAndroidTest
adb -s PHONE shell am instrument -w -r -e modalFixture true \
  belowevolve.airremote.test/belowevolve.airremote.ModalRegressionRunner
```

`ModalRegressionRunner` проверяет окна и подключения. Режимы задаются аргументами:

- `microphoneWithoutCompanion=true` — общий экран ПК/микрофона и закрытие вложенных окон.
- `tvPairingFixture=true` — PIN-сопряжение с тестовым TLS-сервером из `fixtures/`; адрес и DNS-SD-имя задаются `tvFixtureHost` и `tvFixtureName`.
- `bluetoothProgress=true` — лоадер на существующей Bluetooth-паре, выбранной через `bluetoothName`.
- `microphoneSettings=true` — переключатели волны и анимации иконки.
- `screenPreview=tv` — снимок с заголовком «Подключить ТВ», без имени сохранённого телевизора. Настройки и сертификаты сопряжения сохраняются.
- `voiceUi=status` — на эмуляторе с Voice debug снимает короткие и длинные статусы под переключателем прослушивания. Микрофон и команды ТВ не запускает.

Настройки сохраняются перед прогоном и восстанавливаются в конце. После прерванного запуска используйте `restoreOnly=true` с тем же runner.

`SpeechSupportProbeRunner` на Android 13+ запрашивает готовность системного локального распознавания для `ru-RU`: установленные языки, доступные для загрузки и ожидающие загрузки. Он не вызывает `startListening`, не загружает модели и не меняет службу распознавания; может работать с release APK.

`PcNativeImeRunner` и `InputRegressionRunner` проверяют настоящий ввод и могут отправлять команды устройствам: используйте подготовленные тестовые поля и явные параметры сценария в исходниках.

`InputRegressionRunner` с `tvLifecycleFixture=true` поднимает тестовый TLS-телевизор на loopback: проверяет сохранение соединения при сворачивании, готовность в фоне, немедленные нажатия после возврата, отпускание удерживаемых кнопок, восстановление после разрыва и отсутствие модалки во время переподключения. Настоящий ТВ не нужен; настройки и сертификаты восстанавливаются после проверки.

`VoiceControlRegressionRunner` с `mode=transportFixture` отдельно проверяет голосовой
контроллер через настоящий TLS/protobuf. Тестовый ТВ не объявляет поддержку запуска
приложений: питание, медиа и шаг громкости обязаны работать без Air Home. Проверяются
сохранение одного сеанса для OFF/ON, обычная ссылка YouTube и выключение с закрытием
сокета до подтверждения. Настройки, сертификаты и флаг прослушивания восстанавливаются.
Нужны совместимые Voice debug- и тестовый APK из `app/build/outputs/apk/voice/debug/` и `app/build/outputs/apk/androidTest/voice/debug/`.

`mode=standbyProbe` воздействует на настоящий сохранённый ТВ: выключает его, ждёт
150 секунд на контроллере настоящей микрофонной службы с заблокированным
телефоном и включает. Тест без службы не воспроизводит её условия работы в фоне.
`airHome=false` отключает дополнения
для этой проверки; `mode=features airHome=true` включает их обратно для выбранного ТВ.
`standbyMillis` задаёт ожидание
от 500 до 180000 мс; короткий цикл не заменяет штатный 150-секундный прогон.
`IrProbeReceiver` в тестовом APK отправляет один проверенный ИК-импульс;
он защищён системным разрешением DUMP и отсутствует в основном APK.

Для сетевого пробуждения `standbyCommand=TV_TOGGLE` проверяет обычное «Эйр, ТВ»
на контроллере микрофонной службы. Без этого параметра используется TV_ON.
Диагностические `connectionPort=6465` и `wakeKey=26`/`224` выбирают конкретный
канал и один сырой код без восстановления и повторной отправки. Успех
диагностического режима не заменяет проверку обычного голосового маршрута.
Перед замером согласуйте период без ручных команд; внешнее включение делает
результат непригодным для оценки сетевого пробуждения.

`mode=captureRecovery` не отправляет команд ТВ. Он запускает настоящую микрофонную
службу, блокирует телефон и дважды останавливает AudioRecord: запись должна
возобновиться автоматически. Затем debug-only hook моделирует `isClientSilenced`
на пять секунд; настройка остаётся включённой, после снятия флага продолжаются
настоящие аудиосэмплы. Это проверка обработки сигнала Android, а не воспроизведение
политики подавления микрофона конкретной прошивкой. Production APK не позволяет
включить этот hook. Нужен свободный телефон, запись и произнесённые команды
в этот период могут влиять на результат.

`mode=action command=SEEK seekSeconds=900` отправляет настоящую перемотку через
Air Home. Для числовых параметров распознавания проверяются также полученные
значения: +900, -300, +21, −21 и ±10 секунд. Проверяются также «отмотай», отрицания и незавершённые числа. PCM-файлы декодируются без динамика и команд ТВ.

`ScreenPreviewRunner` снимает содержимое окна без системных панелей, шириной до 720 px. Аргумент `screenPreview`: `tv`, `pc`, `pc-collapsed`, `mic`. Снимки сохраняются в `files/screen-previews/` приложения.

Без соединения с ПК доступен снимок исходной развёрнутой клавиатуры (`pc`). Для `pc-collapsed` сначала подключите ПК.

Обычный вариант собирается и проверяется отдельно: `:app:testStandardDebugUnitTest`, `:app:lintStandardRelease`. Его APK не должен содержать Vosk, модель и службы ассистента. Голосовой поиск ТВ и передача микрофона для ПК остаются доступными. PCM-пробы и голосовые runners находятся в `src/androidTestVoice/`.

`editionChecks=standard modalFixture=true` проверяет обычный APK на отдельном эмуляторе: отсутствие службы ассистента и пункта настройки Эйра, удаление тестовой модели прежней Voice-сборки и сохранение выбранного ТВ. Фикстура создаёт только собственную loopback-запись и восстанавливает настройки.
